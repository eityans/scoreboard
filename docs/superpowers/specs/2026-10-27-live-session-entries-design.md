# ゲーム中のセッションを記録する機能

## 概要

ゲームの最中に、参加、リバイ、退出の出来事を記録できるようにする。
ゲームが終わったら、記録から各プレイヤーの収支を計算して、既存の結果（`session_results`）に書き込む。

## 背景

現状のセッション記録は、ゲームが終わってから各プレイヤーの最終収支を 1 つずつ入力する形である。
実際の卓では、途中のリバイ、途中参加、途中退出が起きる。
いまは各自がリバイの回数と入れた点数を覚えておき、「終了点数 − 入れた点数の合計」を暗算して入力している。
たとえば 300 点で参加して 300 点のリバイを 2 回した人が 300 点で終わると、入れた合計は 900 点なので、収支は −600 点になる。
この記憶と暗算をアプリが引き受けるのが目的である。

## ゴール

- ゲーム中に、グループのメンバーなら誰でも、自分のスマホから出来事を記録できる
- 記録から、各プレイヤーの「入れた合計」と収支をアプリが計算する
- 入力を間違えたら、ゲーム中でも終了後でも直せる
- 終了後のセッションは、結果画面、リーダーボード、ダッシュボードで、これまでのセッションと同じように集計される

## やらないこと

- **リアルタイム反映**：別の端末で記録した内容は、手動でリロードして反映する。Turbo Streams などで自動反映する仕組みは作らない
- **既存セッションの移行**：これまでに登録したセッションに記録を後から作らない。記録を持たないまま、今の画面で見たり直したりできる
- **後から入力する流れの置き換え**：ゲーム終了後にまとめて収支を入れる今のフォームは残す

## 失敗とみなす状態

- 記録から計算した収支と、`session_results` の値が食い違う
- ゲーム中のセッションが、リーダーボードやダッシュボードの集計に途中の値で混ざる
- 終了点数を入れ忘れた人がいるのに、セッションを終了できてしまう

## 用語

- **記録**：ゲーム中に起きた出来事 1 件。誰が、何点で、何をしたかを持つ
- **記録の種類**：次の 4 つ
  - **参加**：卓に着いた。入れた点数を持つ
  - **リバイ**：点数を追加で入れた
  - **退出**：卓を離れた。そのときの手元の点数を持つ。ゲーム終了時の終了点数もこの種類で記録する
  - **調整**：結果画面で収支を直したときにアプリが足す。正負どちらの値も取る
- **入れた合計**：あるプレイヤーの参加とリバイの点数の合計
- **着席中**：あるプレイヤーの最後の参加より後に退出の記録が無い状態
- **記録方式のセッション**：「ゲームを始める」から作ったセッション。収支を記録から計算する
- **後入力方式のセッション**：今のフォームで作ったセッションと、これまでに登録したセッション。収支を `session_results` に直接書く

## データモデル

### セッションの状態

`poker_sessions` に状態を持たせる。

```ruby
add_column :poker_sessions, :status, :string, null: false, default: "completed"
```

```ruby
enum :status, { in_progress: "in_progress", completed: "completed" }
```

既存の行はすべて `completed` になる。
今のフォームで作るセッションも `completed` で作る。

記録方式のセッションか後入力方式のセッションかを、別の列で持つ。

```ruby
add_column :poker_sessions, :recorded_live, :boolean, null: false, default: false
```

「ゲームを始める」で作るセッションだけを `true` にし、作った後は変えない。
記録の件数で見分けない理由は 2 つある。
1 つ目に、始めた直後のセッションは記録が 0 件なので、件数で見分けると後入力方式のセッションと判定される。すると今の編集フォームから `session_results` を書けてしまい、ゲーム中の途中の値が集計に入る。
2 つ目に、終了後に記録を全部消したセッションが後入力方式のセッションに変わり、結果の編集画面の挙動が途中で切り替わる。

### 記録

記録を新しいテーブル `session_entries` に持つ。

```ruby
create_table :session_entries do |t|
  t.references :poker_session, null: false, foreign_key: true
  t.references :player, null: false, foreign_key: true
  t.references :recorded_by, null: false, foreign_key: { to_table: :users }
  t.string :kind, null: false             # join / rebuy / cash_out / adjustment
  t.decimal :amount, precision: 12, scale: 1, null: false
  t.timestamps
end
```

- 金額の型は `session_results.amount` と揃える
- 単位の表示は既存の `amount_unit_label(group)` を使う
- 記録の並び順は `created_at` で決める。記録を直しても並び順は変わらない
- 誰が記録したかを `recorded_by` に残し、記録欄に表示する。記録を直した人は残さない
- セッションを消すと、そのセッションの記録も消す（`PokerSession` に `has_many :session_entries, dependent: :delete_all`）。記録のコールバックを走らせないのは、セッションを消している最中に `session_results` を作り直さないためである
- 記録を持つプレイヤーは削除できない（`Player` に `has_many :session_entries, dependent: :restrict_with_error`）。`session_results` を持つプレイヤーと同じ扱いである

### 収支の計算

あるプレイヤーの収支は、そのプレイヤーの記録だけから次の式で決まる。

```
収支 = 退出の合計 − 参加の合計 − リバイの合計 + 調整の合計
```

途中で退出したあと再び参加した人も、この式でそのまま計算できる。

### 記録と結果の関係

記録方式のセッションでは、収支の正しい値は記録の側にある。
`session_results` は記録から計算した値を書き込んだもので、結果画面、リーダーボード、ダッシュボードはこれまで通り `session_results` を読む。

```
後からまとめて入力（今のフォーム）
  └ session_results に直接書く。記録は持たない

ゲーム中に記録する（新しい流れ）
  ├ ゲーム中: 記録を足していく。session_results はまだ作らない
  ├ 終了: 記録から収支を計算して session_results に書く
  ├ 終了後に記録を直す: session_results を計算し直す
  └ 終了後に結果を直す: 差分を調整の記録として足し、session_results を計算し直す
```

2 つの値が食い違わないように、記録の作成、変更、削除の後は、セッションが `completed` なら必ず `session_results` を計算し直す。
計算し直す処理は 1 か所にまとめ、記録の変更と同じ DB トランザクションで実行する。

## 画面と操作

### ゲームを始める

セッション一覧に「ゲームを始める」ボタンを置く。
押すと、`played_on` が今日で `in_progress` のセッションを作り、ゲーム中の画面を開く。

### ゲーム中の画面

`in_progress` のセッションの詳細画面を、記録をつける画面にする。
上から次の順に並べる。

1. 卓にいる人の一覧：プレイヤーごとに、入れた合計、状態（着席中か、退出済みとその点数）、リバイの回数を出す
2. 記録する操作：「参加」「リバイ」「退出」の 3 つ。押すと、プレイヤーと点数を入れて保存する
3. 記録欄：新しい順に、時刻、プレイヤー、種類、点数、記録した人を出す。各行から直したり消したりできる
4. 「セッションを終了する」ボタン

画面はスマホで片手操作することを前提にする。
ボタンは既存の `btn` 系のユーティリティ（最小 44px の高さ）を使う。

### セッションを終了する

参加の記録が 1 件以上あり、全員が着席中でない（全員に退出の記録がある）ときだけ押せる。
押すと、全員の収支を計算して `session_results` に書き、状態を `completed` にする。
終了後は、いつもの結果画面を出す。

### 終了後に記録を直す

`completed` の記録方式のセッションでも記録欄を見られて、直したり消したり足したりできる。
変更のたびに `session_results` を計算し直す。

### 終了後に結果を直す

`completed` の記録方式のセッションでは、結果の編集画面で各プレイヤーの収支を直せる。
`in_progress` のセッションでは、結果の編集画面を開けない。収支がまだ決まっていないからである。
保存すると、変わったプレイヤーごとに「新しい収支 − 今の収支」を調整の記録として足し、`session_results` を計算し直す。
調整の記録も記録欄に並び、ほかの記録と同じように直したり消したりできる。

この編集画面で変えられるのは、収支、日付、メモだけにする。
参加者の追加と削除は記録の側で行う。
結果の画面で参加者を足すと、調整の記録しか持たないプレイヤーができてしまい、記録欄から卓の経過を追えなくなるからである。

### 終了後の変更で、着席中の人ができた場合

終了後に参加だけを足したり、退出を消したりすると、着席中の人ができる。
このとき、セッションを `in_progress` に戻し、`session_results` を消す。
着席中の人の収支は退出の点数を含まないので、そのまま集計すると、実際より大きなマイナスがリーダーボードに入るからである。
全員の退出がそろったら、もう一度「セッションを終了する」を押して `completed` に戻す。

後入力方式のセッションの結果の編集は、今と同じく `session_results` を直接書き換える。

## 集計への影響

`in_progress` のセッションは `session_results` を持たないので、リーダーボードのランキングの合計には入らない。
ただし、セッション一覧、ダッシュボードの最近のセッション、リーダーボードの期間の選択肢とグラフは `poker_sessions` を直接読んでいる。
これらでは次のように扱う。

- セッション一覧、グループ詳細の最近のセッション、ダッシュボードの最近のセッション：`in_progress` のセッションも出し、「ゲーム中」と表示する
- 上の各画面の「N人参加」：今は `session_results` の件数を数えているので、`in_progress` のセッションでは 0 人になる。`in_progress` のセッションでは、記録に出てくるプレイヤーの人数を出す
- ダッシュボードのグループごとのセッション回数：`completed` のセッションだけを数える
- リーダーボードの期間の選択肢とグラフ：`completed` のセッションだけを使う

## 権限

グループのメンバーなら誰でも、ゲームを始める、記録をつける、直す、消す、セッションを終了するの各操作ができる。
既存の `authorize_member!` と同じ判定を使う。

## 実装者に任せること

- 記録の入力 UI の細部（モーダルにするか、画面内のフォームにするか）
- 点数の入力欄の初期値（たとえば、そのセッションで直前に使った参加の点数を入れておく）
- 未登録のプレイヤーをゲーム中に追加する導線（既存の `inline_player_controller` の流用を想定）
- `in_progress` のセッションで日付とメモを直す導線
- 2 人が同時に「セッションを終了する」を押したときの排他（行ロックなど）
- ゲーム中の記録が、着席中でない人のリバイのように順序として不自然な場合の扱い。入力の取り違えを直す途中で一時的に不自然になりうるので、保存時のバリデーションで弾くかどうかは実装時に判断する
